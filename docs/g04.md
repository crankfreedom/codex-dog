# G04 真实 Codex 只读接入实施记录

## 状态与授权边界

- 需求：REQ-20261116-08，2026-11-16（Asia/Shanghai）。当前 Windows 的真实只读链路验证通过。
- 应用 0.4.0-g04、公共 API major=3、数据库 Schema=2；安装更新与发行门禁 G05/G06 尚未通过。
- 只读取额度、会话身份/状态、最新轮次状态和当前 Goal 身份/状态，不发送消息、不消费重置卡。
- 默认仍为 fixture。只有用户明确指定 --source=live-readonly 才连接真实桌面 Codex。
- 不启动独立 App Server，不读取认证文件，不导入旧业务实现、不读旧作业或运行库。
- 不返回或保存聊天正文、会话标题/摘要、原始账号标识、原始工具响应、Goal objective。
- 当前仍为最小配对和状态窗口，没有完整业务界面、托盘、调度、真实任务托管或真实发送授权。

## 实际来源与模块边界

| 能力 | 来源与唯一实现 | 安全边界 |
|---|---|---|
| 桌面发现/连接 | CodexDesktopReadonly → 当前 Windows 的 codex-app-tools-* 管道 | 首次唯一候选或明确 --codex-pipe；不默换到其他实例 |
| 额度 | 桌面 get_usage_limits → CodexReadonlyService | 优先 rateLimitsByLimitId.codex，缺失不回退旧单桶；账号仅内存摘要绑定 |
| 会话分页 | 桌面 list_threads | 固定 history/codex/local，分页 1–50，返回身份及状态 |
| 会话读取 | 桌面 read_thread | 固定本机、turnLimit=1、includeOutputs=false、maxOutputCharsPerItem=0；只投影状态 |
| Goal | CodexGoalReadonly → CODEX_HOME/goals_1.sqlite | readOnly、query_only；指定 thread_id 仅 SELECT goal_id/status |
| 统一接入 | ReadonlyRegistry / HostRouter | CLI/IPC/MCP 共用同一 worker 服务，异步返回前仍复核客户端撤销 |

业务模块只依赖 CodexReadPort、GoalReadPort、时钟/摘要/ID 注入，不依赖 Node、Electron 或具体管道。
基础设施没有任意工具透传口；运行时只允许 get_usage_limits/list_threads/read_thread 三项。
Schema 探测过滤其他工具，并核对必要输入字段；连接、请求、帧和并发均有边界。
桌面原始返回只在内存中解析和投影，CLI 与渲染进程不接触原始 Codex 连接或 Goal 数据库。
能力发现与读取是 Codex 桌面私有桥接机制的本机实测结果，不承诺其他版本永久兼容。

## 启动与明确选择

在工作区根目录 PowerShell 执行：

~~~powershell
pnpm --dir codex-dog build
pnpm --dir codex-dog pack:cli
# 默认模拟模式，保留已有 profile 和配对：
pnpm --dir codex-dog start
# 真实只读，明确提供本机现有调用会话 ID：
pnpm --dir codex-dog start --source=live-readonly --profile=g04-local --codex-caller-thread=EXISTING_THREAD_UUID
~~~

如果由 Codex 工具终端启动，可使用已提供的 CODEX_THREAD_ID；应用会使用该明确环境身份。
普通终端没有该变量时须传 --codex-caller-thread；不会取索引末行作为可靠授权来源。
若桌面管道不唯一，显式传 --codex-pipe=\\.\pipe\codex-app-tools-INSTANCE；不得猜选。
可用 --codex-home=ABSOLUTE_DIRECTORY 明确本机数据根；默认 CODEX_HOME 或用户目录下 .codex。
自定义数据根不代表已证明 Goal 库属于当前账号，接口保留未证实标记。
不要同时用同一个 profile 启动不同来源：单实例锁会保留原窗口；切换来源应先正常退出或使用新 profile。

新版本 CLI 为 release/g04/codex-dog.exe。旧 API 2 严格客户端不能解析新增 live 来源，须重新构建。
API 3 不迁移数据库或授权，默认 profile=g02 延续原配对；g02 是数据空间名，不代表当前版本。

## CLI 与 MCP 使用

先按 [G02 配对手册](g02.md)申请并在桌面批准 read；改用当前 G04 EXE 和同一 profile：

~~~powershell
.\codex-dog\release\g04\codex-dog.exe access request --profile g04-local --client cli --json
.\codex-dog\release\g04\codex-dog.exe connections discover --profile g04-local --client cli --json
.\codex-dog\release\g04\codex-dog.exe connections get --profile g04-local --client cli --json
.\codex-dog\release\g04\codex-dog.exe quota get --profile g04-local --client cli --json
.\codex-dog\release\g04\codex-dog.exe quota refresh --profile g04-local --client cli --json
~~~

从 connections get 取得本次 worker 的 connectionId，再用 JSON 文件或 stdin：

~~~powershell
'{"connectionId":"CURRENT_CONNECTION_UUID","limit":20,"archived":false}' | .\codex-dog\release\g04\codex-dog.exe threads list --profile g04-local --client cli --input - --json --timeout-ms 45000
'{"connectionId":"CURRENT_CONNECTION_UUID","threadId":"EXISTING_THREAD_UUID"}' | .\codex-dog\release\g04\codex-dog.exe threads get --profile g04-local --client cli --input - --json --timeout-ms 45000
'{"connectionId":"CURRENT_CONNECTION_UUID","threadId":"EXISTING_THREAD_UUID"}' | .\codex-dog\release\g04\codex-dog.exe goals get --profile g04-local --client cli --input - --json --timeout-ms 45000
~~~

上例 UUID 为占位符，须使用实际连接和目标；cursor 只能用于相同的 history/source/archived 条件。
MCP stdio 配置使用当前 EXE，args 为 mcp serve --profile g04-local --client mcp --timeout-ms 45000。
MCP 客户端仍独立配对；新增工具 connections_discover/get、quota_refresh、threads_list/get、goals_get 与 CLI 同契约。
共 15 项已实现操作；fixture 模式将六项真实来源操作标为 unavailable，调用返回明确来源错误。
公开目录不包含 threads.send 或卡消费工具，也不向客户端开放任何原始工具名或 SQL。

## 额度、会话与 Goal 语义

- quota.get 返回最近一次真实观察，不触发底层查询；quota.refresh 合并并发刷新，只做读取，不更新调度或创建意图。
- 真实观察只留 worker 内存，不复用模拟 SQLite 快照，不持久化真实额度或正文；应用退出后不可离线读取。
- 返回 source=live、observedAt、stale；三十秒后 available=null、reason=observation_expired，须显式刷新。
- 缺桶/窗口/百分比返回 unknown，不按零消耗处理；非法值报 Schema 错误，预计重置已过去也不自动放行。
- primary/secondary 保留来源窗口及 windowDurationMins/resetsAt，不把所有账号窗口强行命名成固定时长。
- 会话返回 status、statusKnown、activeFlags 和 latestTurn 的 id/status，不透传 turns/items/error 正文。
- notLoaded 如来自当前桌面则仅作为源状态返回；不拿独立 App Server 的缓存状态或无 Goal 推断完成。
- Goal 无行才是 availability=known/current=null；缺库、未知结构、未知状态、损坏/锁冲突为 unknown 和明确 reason。
- Goal 在会话读取前后各读一次；身份或状态变化报 GOAL_IDENTITY_CHANGED，不混合两份观察。
- 每批会话读取前后核对桌面账号摘要；账号变更提升修订、清空缓存并保守停止，要求明确重新选择。
- 账号缺失也清除旧额度缓存；connectionId 改变后旧引用拒绝，异步读取返回前复核客户端授权。

桌面额度与会话来自同一连接并核对前后账号，但 Goal 文件未发现可证实的跨源账号绑定。
因此 goalAccountBindingVerified=false、completionConfirmed=false 始终明确返回，不把 Goal 观察当成真实续跑授权或完成证明。
本次真实目标确认 **无当前 Goal**；六种有行状态的正向覆盖属于临时 Goal 库夹具证据，不冒充真实 active/complete 状态测试。

## 异常与有界等待

| 情况 | 返回与处理 |
|---|---|
| 没有/多个候选、缺明确调用会话 | PROVIDER_UNAVAILABLE 或 PROVIDER_SELECTION_REQUIRED；不猜选、不自动开启其他来源 |
| 工具缺失、Schema/响应不兼容、超大/非法帧 | PROVIDER_SCHEMA_UNSUPPORTED；拒绝，不记录原始响应 |
| 断连或工具拒绝读取 | PROVIDER_UNAVAILABLE；不以旧数据或空会话冒充成功 |
| 单个桌面请求超时 | READ_TIMEOUT；断开当前只读连接，清理在途请求 |
| 缺账号、账号/连接变化 | PROVIDER_IDENTITY_UNAVAILABLE 或 CONNECTION_IDENTITY_CHANGED；丢弃失效缓存 |
| 目标错误、Goal 前后变化 | TARGET_IDENTITY_MISMATCH 或 GOAL_IDENTITY_CHANGED；不返回混合观察 |

单个桌面请求超时为 5 秒；真实 worker 启动等待 15 秒、单次业务读取 30 秒。
本机传输读帧仍限 15 秒；完整请求进入处理后，宿主等待 40 秒、连接处理限 45 秒。
CLI 默认 30 秒，可显式 --timeout-ms 45000；客户端截止并不改变来源事实，所有操作保持只读。
真实来源启动失败保留可诊断的 unavailable 状态，不伪装成 fixture，不因来源异常反复重启 worker。
并发刷新合并，桌面 pending 请求上限 32；现阶段无后台真实额度轮询，不扩大为远程或局域网服务。
