## 数据目录与唯一写入者

当前数据库在 %LOCALAPPDATA%/codex-dog/profiles/<profile>/codex-dog.sqlite。
沿用 G02 当前 SID 保护目录，避免另建未经同样保护的数据根；替代阶段 0 尚未落地的 %APPDATA% 业务路径建议。
主进程将本实例目录注入 worker，只有 worker 组装 SqliteStore 并执行读写。
主进程继续用 access.json 管理技术授权，与领域持久化分离，不迁移或复制客户端秘密到 SQLite。

| 文件/表 | 所有者与用途 | 当前边界 |
|---|---|---|
| codex-dog.sqlite、-wal、-shm | worker 独占的 SQLite 运行文件 | 不手改运行库，不只复制主文件当备份 |
| observations | 按 available/blocked/unknown 场景保存原始模拟额度观察 | 首次初始化持久化，重启复用原 observedAt；quota.get 不增加记录或推进调度 |
| fixture_tasks | 模拟目标、修订、累计次数与上限 | 仅事务验证，不代表公开 tasks 功能 |
| fixture_attempts / fixture_slots | 模拟意图、未决状态与目标槽位 | prepared/uncertain 保留 held，禁止并发重复占用 |
| fixture_events / fixture_operations | 模拟关键事件与原幂等结果 | 和对应变更同一事务提交，不含正文、账号或秘密 |
| fixture-target-locks/ | 仅测试开关下的模拟锁目录 | 不指向旧应用真实锁目录 |

额度调用链为 QuotaService → 注入的 PersistedUsageReader → ObservationStorePort/SQLite 或首次模拟来源。
modules 仅声明窄端口与数据类型，不依赖 node:sqlite、Electron 或具体文件适配器。
构造不读写，显式 start 才开库/迁移；业务退出关闭连接，崩溃由 SQLite 恢复日志。
持久化模拟观察不是实时 Codex 数据，来源始终 fixture，不据此证明真实额度有效性。

## SQLite 选择与迁移

- 使用运行时内置 node:sqlite / DatabaseSync，无新增原生 npm 绑定或外部数据库服务。
- 实际 Electron 45.0.0 的 utilityProcess：Node 24.22.0、SQLite 3.53.4；开发测试 Node 26.7.0。
- 显式启用 WAL、foreign_keys=ON、synchronous=FULL、busy_timeout=1000 ms。
- SQLite application_id=0x43444733；user_version 独立递增，当前为 2。
- 先检查身份、版本和完整性，再迁移；非空外来库、损坏库、未知高版本拒绝，不重建覆盖。
- 空库 → 1 建观察/模拟任务，1 → 2 建模拟意图/槽位/事件/幂等；在单个 BEGIN IMMEDIATE 中递增。
- 注入迁移失败后 schema 和 user_version 一起回滚；已存在的版本 1 模拟任务保留。
- 已知版本还执行固定表查询检查结构，不单凭 user_version 信任数据库。
- 不持有数据库写事务等待网络；当前 SQLite 方法同步、限用于小规模夹具验证，后续大数据导出须分页及取消。

## 已验证的具名事务

| 方法 | 一致性边界 | 验证结果 |
|---|---|---|
| createFixtureTask | 模拟任务 + 创建事件 | 任一步失败无部分任务/事件 |
| prepareFixtureIntent | 租约/修订/次数复核 → 意图 + held 槽位 + 次数 + 事件 + 幂等结果 | 三个写入阶段及提交前租约复核失败全部回滚 |
| markFixtureUncertain | prepared → uncertain + 事件 | 不释放槽位、不回退次数；重启继续保留 |
| cancelFixtureBeforeWrite | 确定未写入的 prepared 取消 + 释放槽位 + 回退对应次数 + 事件 | uncertain 或已处理拒绝，不重复回退 |
| snapshot | 显式只读事务内多表读取 | 并发写提交不会混入当前快照，下一快照才可见 |

准备事务的幂等作用域为 clientId + fixture.prepare + key，参数摘要使用固定字段顺序。
同键同参数返回历史结果，不创建新意图、事件或重复计数；同键异参拒绝。
已有 held 槽位阻止新意图；修订冲突、次数超限和租约目标不匹配均不提交。
幂等记录当前不清理，不能在后续改为清理策略时删除仍未决的意图或原键。
这些方法验证 TX01/TX02/TX03/TX06 所需的基础机制，未声称六类正式业务事务全部实现。
当前没有网络派发；未来的“确定未写入”必须来自真实传输边界证据，不能仅凭状态字符串推断。

崩溃验证在实际 worker 中执行 process.exit：

1. 计数写入后、COMMIT 前结束：恢复时意图/槽位/次数/事件/幂等整体回滚。
2. COMMIT 后、响应前结束：恢复时整笔保留，原键只返回历史结果，不能重发或重新计数。
3. uncertain 状态和 held 槽位跨主应用退出/重启保留；暂停观察不会自动释放或重建。

## WAL 一致备份与失败发布

内部 backup 使用 VACUUM INTO 将运行库的一致快照写入随机临时文件。
验证备份 integrity_check=ok、同步文件后，通过同目录硬链接原子发布，目标已存在即拒绝覆盖。
WAL 中尚未 checkpoint 的已提交数据包含在备份内，不采用复制主 .sqlite 文件的方式。
生成后发布失败会清理临时文件，不留下冒充成功的目标；已有目标内容保持原样。
Windows 对只读句柄 fsync 返回 EPERM，临时文件使用 r+ 打开同步后再发布，已实测。
当前只提供内部适配能力与测试固定目标，不增加任意路径导出或备份 CLI。
断电、磁盘耗尽和超大数据库中断没有进行真实硬件故障测试，不承诺超出 SQLite/OS 保证的恢复能力。
依据：[SQLite VACUUM INTO](https://www.sqlite.org/lang_vacuum.html)、[WAL](https://www.sqlite.org/wal.html)、[事务](https://www.sqlite.org/lang_transaction.html)。

## 旧版目标锁兼容

跨项目文件协议先登记于 [.ai 契约](../../.ai/constraints/api-contract.md)，旧项目源码未修改。
测试直接在隔离子进程加载旧 src/store.ts 的 FileJournal，实际调用 lock(target)，而非重新模拟旧算法。
新 TargetLeaseAdapter 独立实现协议，运行时不导入旧项目；测试只读旧源码、不读取旧作业。

- 文件名为 SHA-256(原始目标 ID UTF-8).lock；内容为 {pid, token}，wx 创建并 fsync 后才算取得。
- 旧版 CODEX_RESUME_LOCK_DIR 可覆盖默认 %APPDATA%/codex-resume/locks，新调用方必须明确核对同一绝对目录。
- 目录未核对、相对路径、网络路径或符号链接根被拒绝，不猜测旧进程的自定义环境。
- 锁存在就阻断，不通过时间戳、窗口存在性、PID 失效或结束其他进程抢锁。
- assertOwned 校验本实例记录、PID、token；释放前复核，已替换 token 的文件保留。
- 当前不自动回收遗留锁。旧版 unlock 的“读后删除”没有并发原子性，不能安全据此自动抢占。
- 真实遗留锁须在停止全部竞争者、核对持有者退出及未决意图后人工处理；没有公开强制解锁命令。

验证覆盖旧持有新拒绝、新持有旧拒绝、释放后取得、同时竞争唯一获胜、不同目标、中文空格自定义目录、异常遗留及 token 替换。
只共享隔离测试目录；本次未使用任一真实目标或旧应用真实锁目录。
G03 证明协议兼容，不代表真实安装环境的旧目录已配置或可开启自动发送；后续仍须核对实际位置与来源授权。
