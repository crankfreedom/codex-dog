## 实际调用链

- 模拟端口：packages/infrastructure/fixture-usage.ts，构造不读取，start 时生成一次快照。
- 唯一业务实现：packages/modules/quota/service.ts；统一注册入口：packages/app/registry.ts。
- Electron 主进程只验证 IPC 来源/本机凭据并转发；apps/desktop/worker.ts 独立持有 ApplicationRegistry。
- CLI/MCP 都通过 packages/infrastructure/local-transport.ts 连接已启动主应用；CLI 打包依赖图不含业务服务或模拟端口。
- IPC 通过沙箱 preload 暴露固定 dog:request 通道，不暴露 Node、数据库或原始 Codex 调用。
- MCP 使用官方 SDK Server、StdioServerTransport；工具名和输入 Schema 来自同一 contracts/protocol.ts，参数最终由同一个主应用处理器校验。

## 已实现操作

| operation | CLI | MCP 工具 |
|---|---|---|
| quota.get | quota get | quota_get |
| app.status | app status | app_status |
| app.version | app version | app_version |
| capabilities.list | capabilities list | capabilities_list |
| capabilities.describe | capabilities describe --operation quota.get | capabilities_describe |

其他规划中的命令返回 CAPABILITY_UNSUPPORTED，退出码 5。未知参数为 INVALID_ARGUMENT，退出码 2；来源和结构检查由统一契约完成。
quota.get 只读初始模拟快照，包含 source=fixture、observedAt、available、两个额度窗口；unknown 场景保留 null，不冒充零或可用。
返回 meta 带 runtimeId、handlerInstanceId、workerPid，端到端比较这些标识和数据证明共用进程中的处理器。

## 启动与场景

先按 [README](../README.md) 构建和生成独立 CLI；默认 profile 为 g01，fixture 为 available。
切换场景时关闭对应验证应用，再启动：

~~~powershell
pnpm --dir codex-dog start --profile=g01 --fixture=available
pnpm --dir codex-dog start --profile=blocked-test --fixture=blocked
pnpm --dir codex-dog start --profile=unknown-test --fixture=unknown
~~~

主应用参数使用 --profile=NAME；CLI 参数使用 --profile NAME，同一次连接必须相同。
available 的两个 usedPercent 为 25/40，blocked 为 100/40，unknown 为 null/40。只有场景构造数据不同，业务实现相同。
开发运行仍需本机 Node 和 Electron 依赖；独立 CLI EXE 已在 PATH 为空时实测，不依赖外部 Node。

## CLI 示例

从工作区根目录运行，主应用须已启动：

~~~powershell
.\codex-dog\release\g01\codex-dog.exe quota get --json
.\codex-dog\release\g01\codex-dog.exe app status --json
.\codex-dog\release\g01\codex-dog.exe capabilities describe --operation quota.get --json
.\codex-dog\release\g01\codex-dog.exe quota get --profile unknown-test --json
~~~

--json 的 stdout 为单个 JSON；诊断写 stderr。--input FILE 或 --input - 可提交参数，quota.get 不接受额外字段。
--timeout-ms 默认 30000，上限 120000；当前全部只读，超时不会触发重试或业务副作用。
--help、--version 可离线使用，查询的是客户端包信息；app version 查询运行中的主应用。

## 通用 MCP stdio 配置示例

不同助手的配置外层格式可能不同，以下展示 command/args 核心字段；修改 command 为本机实际路径。

~~~json
{
  "mcpServers": {
    "codex-dog-g01": {
      "command": "D:/carrey/project/codex-dog/release/g01/codex-dog.exe",
      "args": ["mcp", "serve", "--profile", "g01"]
    }
  }
}
~~~

MCP 桥接可在主应用关闭后保持运行，但业务调用返回 APP_NOT_RUNNING，不自动启动应用。桥接只注册当前五项工具。

## 数据与权限限制

G01 使用系统临时目录 codex-dog-g01/<当前用户摘要>/<profile>，保存临时端点与 Electron 自身缓存，不建立计划中的业务 SQLite。
主应用运行时生成随机会话 token，CLI 读取同用户 profile 的描述文件；退出仅清理本实例端点。此机制仅限模拟原型，Windows ACL、配对、持久权限和恶意同用户程序的隔离均未作为 G02 验证通过。
本次只允许 fixture source 和五项只读能力，不把模拟模式用于消费授权或真实监控。测试使用独立随机 profile，不连接用户正在使用的旧应用。
