> 原计划 0.4 的设计基线按职责迁入本文件；真实只读见 [G04](g04.md)，当前安装更新实现及门禁见 [G05](g05.md)。设计目录不等于已实现能力。

## 实施阶段与交付门槛

实施按依赖推进，不以未验证的工期承诺排期。每个阶段结束后同步计划状态、验证证据和项目档案。

功能阶段遵守[5.5 设计基线](architecture.md)顺序：底层端口与实现 → 统一业务能力 → CLI 验证 → 桌面和 MCP 接入。架构及技术验证只建立支撑该链路的最小宿主，不以 CLI 优先为由允许绕过主应用直接访问数据库或 Codex。

| 阶段 | 内容 | 退出标准 |
|---|---|---|
| 0：范围与契约 | [15 设计基线](roadmap.md)细化数据契约、模块端口、CLI/IPC/MCP 映射、权限、事务、版本政策、旧版互斥策略及验收 | 文档基线与场景可追溯；实施选择和阶段 1 验证门禁明确，不冒充运行验证 |
| 1：技术验证 | 最小 Electron 宿主、底层夹具与首个只读能力；先验证安装后的 CLI/stdout，再接 IPC/MCP；验证管道权限、SQLite、两版 NSIS 更新与文件占用 | CLI 首条完整链路先通过，再证明并列入口复用同一处理器；记录技术证据并锁定版本 |
| 2：架构骨架与只读桌面 | 收敛既有端口/服务/入口/配置/生命周期；按本轮授权提前交付 Vue 主窗口、额度、配对授权与托盘 | 已通过：本机模拟/显式真实只读、安装/驻托盘/退出，远端 CI/Preview，见 [阶段记录](stage2.md) |
| 3：只读与设置 | 会话/Goal 页、分区设置/外观、只读诊断、本应用历史导出和离线说明 | 本机开发版模拟/真实通过；本轮安装及远端 CI/Preview 验收中，见 [阶段记录](stage3.md)；正式任务历史/通知依赖后续业务，不伪造实现 |
| 4：任务自动化 | 托管、授权修订、模板、队列、时段、仅观察、发送与回执、归档；每项先验证业务服务及 CLI | CLI 与桌面/MCP 副作用一致；模拟全链路及恢复通过，未决发送不重复，旧版互斥有效 |
| 5：重置卡与能力覆盖 | 卡片、预约、取消、核对；先完成业务及 CLI，再接桌面/MCP，核对全部产品能力覆盖 | 夹具验证原子领取、幂等、不确定与错过；三入口共用实现，全功能覆盖表无遗漏 |
| 6：更新发行 | 更新服务先经 CLI 验证，再接桌面/MCP；完成签名、整包安装协调、接入文档和恢复说明 | 真实安装版升级通过；进程清理、数据升级、损坏包与失败恢复验证，各入口不绕过安装门禁 |

阶段 0 的文档设计基线已完成；阶段 1 的 G01–G04 及 G05 当前 Windows x64 模拟安装更新已通过，G06 尚未通过。技术门禁通过不代表全部计划功能、正式签名发行或跨平台支持已经实现。

## 定案范围与状态

本节将讨论方案细化为后续实现应遵循的文档契约。属于工程设计基线，不代表用户逐一指定了内部名称或默认参数；后续若改变公共语义，须先修订本节及相关验收。端口签名以下面的输入、输出和失败语义表达，阶段 0 未创建 TypeScript、Schema 文件或测试代码；当前 G01–G03 模拟基础与 G04 真实只读已获用户授权并完成相应验证，具体证据见对应实施记录。

- 定案：模块职责与数据归属、底层端口、公开操作及 CLI 映射、默认边界、并发和未决语义、验收场景。
- G01 已验证 Electron 45、TypeScript 5.9、Node SEA CLI 与多入口模拟链路；G02 已验证当前 Windows 的管道 ACL 与配对生命周期；G03 已验证 SQLite 与隔离旧版锁互斥；G05 已验证测试 NSIS、GitHub 下载、安装及退出。真实锁配置、正式签名与 Actions 仍待后续验证。
- 阶段 0 未开展源码初始化；当前授权 G01–G03 模拟基础及 G04 真实只读；真实额度/会话/Goal 仅查询，不发送、兑换、读取认证或发布。

- 最小技术链路按“底层夹具 → quota.get 业务处理器 → 已启动宿主中的 CLI → IPC/MCP 等价调用”推进，不先写完整界面或通用框架。
