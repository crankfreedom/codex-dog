## 运行与首次配对

在工作区根目录使用 PowerShell，先构建并启动主应用：

~~~powershell
pnpm --dir codex-dog build
pnpm --dir codex-dog pack:cli
pnpm --dir codex-dog start
~~~

默认 profile=g02、fixture=available。开发构建使用 Node 26+、pnpm 11.20。
Windows 管道适配使用系统 Windows PowerShell 5.1/.NET Framework，隐藏窗口运行；不会更改系统执行策略。
系统策略若禁止执行宿主脚本则启动失败并拒绝开放服务，当前未验证受限企业策略环境。
独立 CLI 内置 Node；release/g02/codex-dog.exe 是未签名控制台验证产物，尚非桌面安装器。

在另一终端申请默认只读权限：

~~~powershell
.\codex-dog\release\g02\codex-dog.exe access request --client cli --json
~~~

返回 pending、id、revision 和六位大写十六进制 code。申请不会直接获得读取权限。
在桌面找到同一申请，核对客户端及配对码，输入该码后点击批准；申请有效期为五分钟。
批准后即可调用：

~~~powershell
.\codex-dog\release\g02\codex-dog.exe quota get --client cli --json
.\codex-dog\release\g02\codex-dog.exe app status --client cli --json
.\codex-dog\release\g02\codex-dog.exe capabilities list --client cli --json
.\codex-dog\release\g02\codex-dog.exe capabilities describe --operation access.revoke --client cli --json
~~~

客户端名称只是本地凭据文件的选择项和展示标签，服务器通过随机 clientId 与秘密验证身份。
不要把秘密放入参数、日志或示例。CLI 自动生成并保存秘密，配对结果不会输出秘密。
配对超时、撤销或授权到期后，使用新的 --client 名称重新申请；旧身份不会自动恢复或续权。
完全退出后调用返回离线错误，不会自动启动应用；同 profile 重复启动只激活原实例。

## 管理权限、批准与撤销

G02 仅实现 read 与 access.manage。后者能批准及撤销客户端，必须由用户明确批准。
它不代表未来的任务管理、消息发送、卡片消费或其他应用管理权限。
普通 read 客户端不能自授、列出或管理其他客户端。

需要从脚本管理配对时，先申请两项权限：

~~~powershell
'{"clientLabel":"local-admin","requestedScopes":["read","access.manage"]}' | .\codex-dog\release\g02\codex-dog.exe access request --client admin --input - --json
~~~

桌面核对 code，明确勾选访问管理权限后批准。随后从 access list 获取目标的最新 id/revision：

~~~powershell
.\codex-dog\release\g02\codex-dog.exe access list --client admin --json
~~~

批准输入示例，替换为真实申请字段，不能复用示例 UUID 或配对码：

~~~json
{
  "id": "11111111-1111-4111-8111-111111111111",
  "expectedRevision": 1,
  "code": "A1B2C3",
  "scopes": ["read"],
  "expiresAt": null
}
~~~

~~~powershell
.\codex-dog\release\g02\codex-dog.exe access grant --client admin --input grant.json --idempotency-key approve-client-001 --json
'{"id":"11111111-1111-4111-8111-111111111111","expectedRevision":2}' | .\codex-dog\release\g02\codex-dog.exe access revoke --client admin --input - --idempotency-key revoke-client-001 --json
~~~

expiresAt 输入为带时区的未来 ISO 时间或 null；当前授权 DTO 的时间字段返回毫秒时间戳。
只能授予申请过且管理员自身拥有的权限。批准与撤销必须携带 expectedRevision 和幂等键。
同一调用者、操作、幂等键和参数返回原结果；相同键换参数返回 IDEMPOTENCY_CONFLICT。
授权操作串行提交，原子保存失败不更新内存；未知高版本或损坏授权文件阻止启动，不静默重建。
保存的幂等记录保留三十天，最多 2048 项；客户端最多 1000 个，有效待配对最多 32 个。
重试必须保留原键和参数；历史返回是原操作结果，当前权限以新读取的状态为准。
撤销提高修订并清空权限；CLI 与已有 MCP 会话的后续调用立即失效。
异步额度读取在返回前再次复核修订，撤销发生于在途读取时不再返回数据。

## MCP 使用

助手的 stdio 配置示例，替换路径为本机实际绝对路径：

~~~json
{
  "mcpServers": {
    "codex-dog": {
      "command": "D:\\carrey\\project\\codex-dog\\release\\g02\\codex-dog.exe",
      "args": ["mcp", "serve", "--profile", "g02", "--client", "mcp"]
    }
  }
}
~~~

先调用 access_request，参数为 clientLabel 与 requestedScopes，再到桌面核对批准。
默认 CLI 和 MCP 分别使用 cli、mcp 凭据，相互独立配对；不同助手应选择不同 --client。
九项工具的业务参数来自同一契约；变更工具另接受 idempotencyKey，并映射至请求元数据。
授权管理工具的重试应显式保留该键；申请未传键时按 clientId 生成稳定申请键。
桥接不执行普通 CLI 子命令、不自动启动应用；应用重启后在后续工具调用时重新发现端点。

## Windows 身份与传输边界

- 数据位于 %LOCALAPPDATA%/codex-dog/profiles/<profile>/，默认 profile 为 g02。
- 目录 DACL 受保护、关闭继承，仅当前 Windows SID 拥有完全控制；客户端文件继承该保护。
- 命名管道显式 DACL 仅允许当前 SID，并拒绝网络登录；同时使用拒绝远程客户端标志。
- 首实例使用 FILE_FLAG_FIRST_PIPE_INSTANCE；同名管道预先被占用即拒绝启动，不发布新端点。
- 宿主读取有界帧后调用 RunAsClient 取得实际 SID，主进程复核；身份不来自客户端 payload。
- 最多 16 条活动连接并保留一条监听；请求上限 1 MiB、响应上限 4 MiB，均带超时。
- 每实例生成独立通道密钥；AES-256-GCM 对请求和响应认证加密，绑定实例、方向及请求随机数。
- 陈旧端点对应的伪造同名服务只能收到密文，未经认证的成功响应被拒绝。
- endpoint.json 包含实例和通道密钥，该密钥只用于传输保护，不能代替客户端配对授权。
- clients/<name>.json 保存随机秘密；access.json 仅保存秘密摘要、授权、修订和幂等记录。
- 当前采用受 ACL 保护的文件，未使用 DPAPI；不能承诺隔离同账户恶意代码、管理员或 SYSTEM。
- 实测核对了实际 DACL，并用匿名模拟身份连接确认拒绝；未创建第二个 Windows 账户做登录测试。

当前 API major 从 G01 的 1 升为 2：共享会话 token 被客户端身份、配对授权及认证通道替代。
旧 G01 EXE 不能连接当前服务，应重新构建配套客户端；不做静默协议降级。
最低 Windows 版本、ARM64 和 macOS 尚未验证，macOS 保留传输适配边界。
Windows 安全依据参见 [Microsoft 命名管道访问控制](https://learn.microsoft.com/en-us/windows/win32/ipc/named-pipe-security-and-access-rights)。

## 心跳、有限重启与退出

| 项目 | 当前值及语义 |
|---|---|
| worker 心跳 | 每 500 ms，监视器每 250 ms 检查，使用单调时钟 |
| 心跳超时 | 2500 ms；拒绝在途读取，终止失联 worker 并进入恢复 |
| worker 启动超时 | 5000 ms |
| worker 读取超时 | 5000 ms；只读返回 READ_TIMEOUT |
| 重启预算 | 每次主应用运行最多三次，退避 300/600/1200 ms；ready 不重置预算 |
| 预算耗尽 | state=failed、reason=restart_limit_reached，不再无限拉起 |
| 正常退出 | 阻止新请求，删除本实例端点，关闭管道宿主、worker，等待授权提交结束 |
| 子进程停止 | 各有 3000 ms 退出等待，超时终止；退出取消已排队重启 |
| 主应用异常结束 | 管道宿主检测 stdin EOF；worker 每 750 ms 检查父 PID，结束自身 |

app.status 返回 state、workerPid、inFlight、heartbeatAgeMs、restartCount、maxRestarts、reason。
恢复期间业务请求返回 APP_NOT_READY；退出期间返回 APP_STOPPING，正常退出后为 APP_NOT_RUNNING。
写请求发出后超时或断连返回 OPERATION_UNCERTAIN，不能推断未保存，须保留原幂等键核对。
异常退出可能留下旧 endpoint.json，但服务不会因此复活；下次手动启动发布新实例与通道密钥。
正常及异常重启后授权和撤销记录保留；不恢复旧客户端已撤销的权限。
